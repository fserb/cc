paste mark: a one-colour stand-in for 🖼

Today a pasted image is 🖼 (U+1F5BC) in the say box and in the chat log. It draws in colour, from Apple Color Emoji on the Mac and Noto Color Emoji on Android, and in the blue bubble it is the one thing that is not white. cchost replaces each mark with the image's path (host/jump.js IMAGE; typed.js and queue.js match it too), so the mark has to be one fixed character, or one fixed sequence, that people do not type.

The "this browser" lines are measured when the page loads: each mark is drawn on a canvas in cc's font, and the page checks for coloured pixels and for the missing-glyph box. Open the page in Arc and on the phone to get those two answers.

Width: advance in em in cc's font, and in cells of the mono font (1 = one "0"). cc shows the mark in the textarea and in bubbles, both in cc's font; the terminal view shows Claude Code's own [Image #N], not the mark, so the mono width matters only if a mark is ever drawn in mono.

Pick: F, the same 🖼 drawn by a one-glyph font

Keep U+1F5BC as the stored character and draw it with a 728-byte font (inline in the CSS, base64) whose only glyph is an outline picture frame, mapped by unicode-range: U+1F5BC, put first in the textarea's and the chat's font-family. It takes the text colour (white in the blue bubble), looks the same on every browser because the glyph comes with the page, and changes no code: the say box, cchost, typed.js, queue.js, old drafts and logs all keep 🖼. A copy out of the box still gives 🖼, which reads right anywhere else.

Its costs: the glyph is my drawing (it can be redrawn: it is a few polygons in a 40-line fontTools script); and a 🖼 a person types or an agent writes in a reply shows as the outline frame too, which is arguably right.

If a new font is not wanted, the best plain character is ⎙ (U+2399, print screen symbol): one UTF-16 unit, never an emoji on any platform, rarely typed. But it reads as "print", not "picture", it needs the character changed in index.html and three cchost files plus a reader for old 🖼 drafts, and on Android it depends on a symbol font I could not check. 🖼︎ (with U+FE0E) is the weakest: two code points to split on, a caret can land between them, and on the Mac and Android no text font has U+1F5BC, so Chrome draws it in colour anyway.

Sources

  • U+1F5BC is Emoji=Yes, Emoji_Presentation=No, so it defaults to text, but a browser draws it from whatever font has it: emoji-data.txt. U+FE0E only asks for text; Chrome falls back to the colour font when no other font has the glyph: UTS #51 §1.4.3.
  • 📎 U+1F4CE is Emoji_Presentation=Yes and has no standard text variation sequence in emoji-variation-sequences.txt, so U+FE0E after it is not a defined sequence.
  • Font coverage on nadya: fc-list ":charset=1f5bc" lists Noto Color Emoji and Noto Sans Symbols 2 only. Android ships Noto Color Emoji and subsets of Noto Sans Symbols; which of the 1F5xx pictographs those subsets keep I could not confirm, hence "?".
  • unicode-range font override: MDN; supported in every Chromium.
