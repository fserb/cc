A diff page in cc: review a session's change, comment and decline line by line

Mock for the user's ask (Oct 19th): "design a diff page that shows a change diff (side by side and unified options) that I can review changes, comment / decline line by line". Nothing is implemented in cc or cchost. The frames below are one working page (this file with ?app) drawn at desktop width and at the phone's 448 px; click and type in them. The data is a real commit, 5773960 in nadya:~/ai/cc, "away mode in cchost" (5 files, +261 −2), with a review already started: 2 comments and 2 declines. cc-d, Oct 19th.

Open the page alone: desktop or phone, whatever this window is · unified · with the review open · jump to the phone views

1. Desktop: side by side

Files on the left with their state (○ not viewed, ✓ viewed, then the comments and declines in each); the diff on the right, one section per file, its header stuck to the top while you scroll it. Click a line number to start on a line; shift-click, drag, or click a second number while the box is empty to make it a range. One box for both actions: Comment sends the text as a note, Decline sends it as the reason to undo those lines. A hunk's header has "comment on hunk" and "decline hunk"; the file header has "viewed".

2. Desktop: unified, and sending the review

The switch in the header (Unified / Side by side) is kept per device. Review opens the summary: every comment and decline (each a link to its line), an overall note, the exact text the session gets, and the send button. The verdict follows from what is in it: any decline is "changes requested", only comments is "comments", nothing is "looks good".

3. The phone (Pixel 9 Pro XL, 448 px)

Unified only: two columns of code at 448 px are about 25 characters each. Side by side comes back when the phone is turned sideways (997 px is a desktop width). Code wraps instead of scrolling sideways; one line-number column (the new number, the old one on removed lines). The file list is a bar with ‹ › and a sheet. A tap on a line number opens the box under it; a tap on a second number while the box is empty makes the range. All targets are 44 px or more.

4. How a change gets to this page

Assumed: cc learns a session's commits from its own transcript (a Bash git commit whose output has [main 5773960]), not from git log, because cc-a, cc-b and cc-c all commit to ~/ai/cc as the user and the author can't tell them apart. The page's address is /cc/#diff/nadya:~/ai/cc@5773960 (a range is @a..b, the working tree @work), so every entry point below is a plain link.

5. What "decline" does (assumed)

Declining is a request to the agent, not an edit by the page: cc never changes the repo. When you send, the session gets one message, typed into its prompt as you (the same path as ccx user --as cc, so it shows as a cc side quote and queues behind a running turn). It says, per declined line or hunk: take it out (an added line), put it back (a removed line), and do what the reason says instead; per comment: answer or act on it. The agent does it as a new commit (no amend, no force push), runs the tests, and replies with the hash. The review stays on this page, read-only, with "diff since your review" once that commit exists. With no declines and no comments the button says Looks good and the message is one line.

6. Not picked

  

    
The page reverts declined lines itselfcchost would git apply -R the hunks. Picked the agent instead:
      a revert usually breaks something nearby (an import, a test, the docs), the agent knows what, and cc stays out of the
      repo. Could be a later "revert now" button for a whole file.

    
Approve / Comment / Request changes (GitHub)Three buttons for a one-person review. The verdict here follows from
      the content; one Send button.

    
Votes and patch sets (Gerrit)Code-Review −2..+2 per change, every revision kept as a set. Too heavy; only "diff
      since your review" is kept from it.

    
Each comment sent as you write itInterrupts the agent once per line, and a later comment can contradict an
      earlier one. Batched in one message, like a GitHub review.

    
Suggested edits (GitHub "suggestion" blocks)Typing replacement code on a phone is slow; the reason text covers it.
      Open point below.

    
Swipe a line to decline (phone)Hidden, and easy to set off while scrolling a diff. A tap on the number, then a
      button, is two taps and visible.

    
Side by side on the phone~25 characters a side at 448 px. Unified with wrapping; sideways works.

    
Send through SendMessageA peer message reaches the session only at its next turn boundary, and many were never
      delivered (CLAUDE.md, "Messaging another instance"). Typing is what ccx user already does reliably.

    
Open plannotator's review UI insteadIt runs a local server per review and opens a browser on that machine; not
      reachable from the phone, and not tied to the session that made the change.
